# Execution Policy

## 목적
AI 또는 개발자가 수행하는 코드 변경 작업의 실행 기준을 정의한다.

---

## 1. 기본 원칙

- 기존 동작을 절대 깨지 않는다
- 최소 변경만 수행한다
- 불필요한 수정 금지
- 구조 변경 금지

---

## 2. 작업 단계 규칙

모든 작업은 아래 순서를 따른다:

1. 분석 (코드 수정 금지)
2. 영향 범위 확인
3. 위험도 판단
4. 승인
5. 최소 단위 변경
6. 테스트
7. 롤백 가능성 확인

---

## 3. High Risk 작업 정의

아래 작업은 High Risk로 간주한다:

- Controller 수정
- Repository 수정
- DELETE 쿼리 변경
- UPDATE 쿼리 변경
- DB 연결 관련 수정
- appsettings.Production.json 수정
- 인증/로그인 로직 변경

---

## 4. High Risk 작업 규칙

High Risk 작업은 반드시 아래를 따른다:

- 분석 단계 필수
- 사전 승인 필수
- 한 번에 하나의 변경만 수행
- 변경 후 테스트 필수
- rollback 방법 명시 필수

---

## 5. 금지 작업

다음 작업은 금지한다:

- DB 스키마 변경
- 대규모 리팩토링
- 파일 구조 변경
- 다수 파일 동시 수정
- 영향 범위 불명확한 변경
- "정리" 또는 "개선" 목적의 변경

---

## 6. 자동 중단 조건

다음 조건 발생 시 작업을 중단한다:

- 영향 파일이 3개 이상
- Controller + Repository 동시 수정
- DELETE + UPDATE 동시 포함
- DB 구조 관련 변경 감지
- rollback 방법 없음

---

## 7. 허용 작업 (Low Risk)

다음 작업은 비교적 안전하다:

- 로그 추가
- null 체크 추가
- 에러 메시지 개선
- 주석 추가
- 단일 파일 내 소규모 수정

---

## 8. 출력 규칙 (AI 작업 시)

코드 변경 전 반드시 출력:

- 변경 파일 목록
- 변경 이유
- 예상 영향
- 위험도
- rollback 방법

코드 변경 후 반드시 출력:

- 변경 diff
- 테스트 방법
- 영향 범위 요약
