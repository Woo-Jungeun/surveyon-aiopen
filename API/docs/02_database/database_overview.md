# Database Overview

## 1. 목적
본 문서는 현재 프로젝트의 DB 사용 구조와 운영 원칙을 정의한다.

이 문서는 DB 구조를 변경하기 위한 문서가 아니라,
기존 DB 사용 방식의 안정성을 유지하기 위한 기준 문서이다.

---

## 2. 사용 DB

- PostgreSQL
- MSSQL

확인 필요:
- 운영 / 개발 환경 분리 여부
- 실제 운영 DB 종류
- DB별 역할 분리 여부

---

## 3. 애플리케이션 접근 구조

Controller  
→ Service  
→ Repository  
→ DB

설명:
- Controller: 요청 진입
- Service: 비즈니스 로직 처리
- Repository: DB 접근 및 쿼리 실행

주의:
- DB 접근은 Repository 계층을 통해서만 수행해야 한다
- Controller에서 직접 DB 접근 금지

---

## 4. 연결 설정 위치

- appsettings.json
- appsettings.Production.json

확인 필요:
- 환경변수 사용 여부
- DB 연결 문자열 관리 방식

주의:
- 운영 DB 연결 문자열 변경 시 전체 시스템 영향 가능
- 설정 변경 전 반드시 영향 범위 확인 필요

---

## 5. DB 사용 원칙

- 현재 DB 구조를 변경하지 않는다
- 운영 DB에 직접 스키마 변경을 수행하지 않는다
- SQL 수정 전 반드시 영향 범위를 확인한다
- Repository 쿼리 변경 시 회귀 테스트 필수
- 대량 데이터 처리 로직은 사전 검토 후 수행한다

---

## 6. 보안 원칙

- SQL Injection 방지를 위해 매개변수화된 쿼리 사용
- 민감 데이터는 직접 노출하지 않는다
- DB 접근 권한은 최소 권한 원칙 적용

---

## 7. 고위험 작업 정의

아래 작업은 High Risk로 간주한다:

- DELETE 쿼리 변경
- UPDATE 쿼리 변경
- DB 스키마 변경
- 인덱스 변경
- 대량 데이터 처리 로직 변경
- DB 연결 방식 변경

→ 반드시 사전 분석 및 승인 필요

---

## 8. 금지 사항

- 운영 DB에 직접 ALTER 실행 금지
- 승인 없는 스키마 변경 금지
- 구조 개선 목적의 리팩토링 금지
- 쿼리 최적화를 이유로 한 구조 변경 금지
